# Changelog

All notable changes to immutable-test-builder are recorded here. This project follows [Keep a Changelog](https://keepachangelog.com/en/1.0.0/) and [Semantic Versioning](https://semver.org/spec/v2.0.0.html). What a perfect default is, and why a builder refuses loudly instead of building a lie, lives in the [README](README.md).

1.0.0 is the first public release and the point the surface freezes. Everything described in the README is under the SemVer promise from here on.

## [Unreleased]

### Added
- **`CostlyCallInSeedRule`, the first rule about cost rather than contract, in its own include and open to extension.** `seed()` runs on every `create()`, so a suite pays whatever is in it once per builder it makes, and one `password_hash()` at bcrypt cost 4 measures around 888 microseconds - the price of 617 derived modifier calls for a single seeded password. The rule ships `password_hash()` and `crypt()`, which is PHP's own password API where a work factor is the documented purpose, and it guesses at no third entry. A general key derivation like `hash_pbkdf2()` is left out on purpose, because it also derives encryption keys where a test may want the real thing. Everything else expensive is the project's knowledge rather than ours, so a project declares it through `immutableTestBuilder.costlyInSeed`, naming a function or a `Class::method` and the reason it belongs there. Requiring that reason is the point - it lands in the message somebody has to act on, and a rule that cannot say WHY a call is slow is an opinion wearing a rule's clothes. Instance calls are not matched, deliberately, since a builder holds no injected service with the constructor sealed. What may be declared is bounded too, and the docs say so - only a call returning an immutable VALUE, because the advice is to hoist or memoise and one object instance shared by every builder would mutate for all of them at once. A nested builder is the clearest thing not to declare, since a related entity a valid default needs is what makes the default valid rather than a cost to remove. Because it says a builder is expensive rather than wrong, it lives in `Rule/Performance` and ships in `config/performance.neon`, leaving the nine contract rules unmixed, and it is dogfooded on this package's own analysis.
- **Every rule states the node it is handed, so an IDE reads them as cleanly as PHPStan does.** `@implements Rule<InClassMethodNode>` is enough for the analyser to know what `$node` is, and invisible to an editor, which then marks every `getOriginalNode()` call as undefined. A `@param` beside it costs nothing and buys back the whole file, so all ten rules carry one naming their own node type.
- **`PerfectDefaultPropertyRule` asks the shared gate instead of repeating it.** It had `BuilderScope::concrete()` followed by its own `isSubclassOf(AbstractBuilder::class)`, which is what `BuilderScope::kernel()` already is, so the one coupling between the analysis and the kernel class existed in two places for no reason. It now exists in one, and no rule imports `AbstractBuilder` any more. The remaining mention sits in the reflection extension, which is handed a `ClassReflection` rather than a `Scope` and so cannot use the same gate.
- **The benchmark suite gained a builder the size of a real one.** The fixtures beside it hold a handful of ingredients, which is enough to prove behaviour and useless for pricing it, so `ColonyBuilder` carries twenty and half of them wear handwritten modifiers. That lets a chain of ten derived calls be read against a chain of ten declared ones on the same object instead of across two fixtures, and it settles the question the small subjects could not answer. Deriving costs a CONSTANT multiple rather than a growing one - the tenth link in a chain prices at 2.04 microseconds against the first at 1.89, so the memo holds and neither chain length nor property count moves it. Ten derived land at 20.4 microseconds against 6.9 for ten declared, and `create()` over twenty ingredients at 0.41. The number that matters is the last one, because whatever a project puts in its own `seed()` dwarfs all of it. One `password_hash()` at bcrypt cost 4 measures 888 microseconds, which buys 617 derived modifier calls.

## [1.1.0] - 2026-08-03

The kernel gets measured, and the measurement pays for itself on the first run. A minor rather than a patch because the improvements are substantial and land in private code, which is the case SemVer names explicitly. The public surface has not moved.

### Added
- **A PHPBench suite under `benchmark`, stated in ratios and never in seconds.** A duration means nothing on somebody else's hardware, so every subject exists to be read against another subject. `PrefixBenchmark` proves the grammar lookup costs the same for every prefix, `MagicModifierBenchmark` prices a derived modifier against a handwritten one that ends in the same `mutate()`, which makes the gap the price of not writing the method, and `KernelBenchmark` shows a chain of ten modifiers landing near ten times one rather than near a hundred. `composer benchmark` reads them, `composer benchmark:baseline` stores this machine's numbers and `composer benchmark:check` fails on drift beyond a tolerance. CI runs the suite once with a single revolution, proving the benchmarks still execute without asserting a stopwatch a shared runner cannot hold still. The directory is `export-ignore`d, so nothing here reaches an installed package.
- **The chained-call style is enforced instead of remembered.** A multi-line fluent chain closes with its semicolon on its own line, which was the style everywhere in the kernel and had already drifted in three places. `multiline_whitespace_before_semicolons` now holds it, and the rule caught a fourth case in the fixer's own configuration on its first run.
- **The prefix boundary is pinned in both directions.** `PrefixTest` now covers a digit opening a property name (`with2FA`), a capitalized prefix being refused, a name shorter than any prefix, and an empty name. Four cases that could have quietly narrowed the boundary set with no test noticing.
- **How a union-typed ingredient derives is pinned too.** The rule was already in force and agreed between the runtime and the analysis, but nothing recorded it, so a well-meaning patch could have widened it unnoticed. A union derives where the operation does not have to pick a member of it, which is `with*` alone. `without*` would have to choose between an empty array and an empty string, and `including*` would append with `[]=` against whatever the property currently holds rather than what it was declared as, so both refuse instead of working by luck. `UnionBuilder` and five tests hold that line. A nullable is not a union to reflection, which is why `?array` keeps deriving normally.

### Changed
- **`Prefix::ofMethod()` stops building a pattern and stops asking the cases.** 1.0.0 assembled a regular expression with `sprintf()` and handed it to `preg_match()` once per enum case, so one magic modifier paid for up to eight pattern builds before the resolver even looked at a property, and what a prefix cost depended on where it sat in the enum. A method name already states where its own prefix ends, at the lowercase run before a property name begins, so resolution now finds that boundary once and looks the value up. No pattern is compiled, no case is asked and none is walked past. `Prefix::ofMethod('withCallsign')` falls from 1.90 to 0.33 microseconds, a name from outside the DSL from 1.06 to 0.36, and the cost goes flat across the whole grammar, moving only with how many characters a prefix has. The grammar answers exactly as it did, proven by diffing a table of nineteen method names either side of the change. Declaration order now carries no weight in cost or in meaning, so the cases stay in reading order, and `matches()` answers through `ofMethod()` instead of comparing for itself, which leaves the grammar parsed in exactly one place.
- **The derivation is memoised, so reflection happens once per builder instead of once per call.** Profiling the magic path showed the grammar lookup had stopped being the cost and the reflection behind it had become it, so four immutable facts are now remembered - the `ReflectionClass` per class, the stateless writer per prefix, the resolved target property per class and method, and the set of writable instance property names per class. Each is a lookup table over something a running process cannot change, held in the function that reads it rather than behind a cache object, because a dedicated one measured 1.6 to 2.4 times slower per hit than the local `static` it would replace. A derived modifier falls from 2.41 to 1.79 microseconds, the map dialect of `mutate()` from 0.80 to 0.69, and a chain of ten from 7.62 to 6.43. The property memo is keyed by class AND method, since the same method name reaches a different property on every builder that declares it, and a test drives `includingCargo()` through two fixtures that disagree about the type of `$cargo` to keep that key honest.
- **`Prefix::PROPERTY_START` declares its type.** Every other constant in the package is typed and this one was not.
- **The README title reads as a name rather than a slug.** The repository name already states the identifier, so the heading no longer repeats it in the same viewport.
- **Every CI action is pinned to a commit SHA**, the only reference an upstream cannot move underneath the build, each carrying the version it stands for as a comment. Dependabot keeps the pins from going stale.
- **Every `match` over the grammar is exhaustive now.** `propertyCandidates()` still carried a `default` arm, so a new prefix would have quietly inherited the singular instead of being made to say whether it speaks plural, which is the one thing the neighbouring methods are documented never to allow.

- **A writer takes a name and a type, not a `ReflectionProperty`.** The four writers that read the declared type shared a base class whose whole job was unpacking that property for them, which traded four copies of the unpacking for one extra call on every magic modifier. The resolver unpacks once at the single place it already holds the property, so `AbstractTypeAwareWriter` is gone, every writer implements the interface directly, and none of them depends on `ReflectionProperty` any more. `with*` is the one that ignores the type it is handed, because an assignment never has to pick a value the way emptying and the collection prefixes do.

### Fixed
- **A readonly ingredient inherited from an abstract base no longer escapes as a bare `Error`.** `WritableStateRule` forbids readonly state, but it gates on concrete builders and an abstract base is exempt, so a base could hand one down and both write paths would sail past their guards straight into PHP's own `Cannot modify readonly property`. That is the same shape the collection writers were fixed for in 1.0.0, found this time by walking the inheritance edges rather than by a report. Both paths now refuse by name, and because the check sits in the one predicate the PHPStan extension shares, the modifier stops being advertised in analysis at the same moment it starts being refused at runtime. Worth knowing why the shape is a trap at all - readonly cannot carry a default, cannot be assigned from the concrete scope, and a builder cannot declare a constructor because the kernel seals it, so it is state PHP will let you write once and no analyser will bless.
- **The map form of `mutate()` refuses a static key, which it already promised to do.** Its docblock said a key the concrete scope cannot write is refused loudly, yet `property_exists()` answers true for a static property, so the key passed the guard and the bound write went nowhere - a modifier that reported success and changed nothing. The guard now rejects it by name and says a clone would not carry static state anyway. Reaching this needed a builder that already breaks `WritableStateRule`, so no correct builder changes behaviour, and the cost is a tenth of a microsecond on the map dialect alone.

## [1.0.0] - 2026-08-02

One grammar, three readers that cannot disagree. The DSL is declared once as an enum, the kernel implements it from your property declarations, and the bundled rule set turns it into analysis errors - so a builder is correct by construction, typed without annotations, and refuses loudly the moment it cannot be.

### Added
- **The `BuilderInterface` contract - a perfect default in, a valid object or a loud refusal out.** Two methods are the whole promise. `create()` returns a builder that `build()`s successfully with no further calls, so a test states only the values it asserts on. `build()` returns the target object or throws `UnbuildableState` - it never hands back a half-thing. The interface is covariant over what it builds, so a `BuilderInterface<Admin>` passes wherever a `BuilderInterface<User>` is asked for. Contracts live under `Contract` (the interface, the `Prefix` vocabulary, the exception), the engine under `Implementation`.
- **Magic modifiers - the trivial ones stop existing as code.** `__call` hands the call to `ModifierResolver`, which maps the parsed prefix to one writer per prefix - `with*` assigns, `without*` empties by inferred value, `as*` sets a flag, `including*` appends, `excluding*` filters - straight from property declarations, with `Closure::bind` writing sealed private state without unsealing it and collection prefixes resolving the simple plural. `as*` takes an optional bool - `asArmed()` raises the flag, `asArmed(false)` lowers it, `asMothballed(null)` clears a nullable one. Every derivation fails loudly instead of writing a lie - named arguments are refused (magic reads positionally), so are a non-bool flag, a non-array collection and an un-inferrable empty value. `from*`, `for*` and `having*` stay handwritten and a declared method always wins. Two attributes tune the derivation from the property side - `#[Plural(of: 'person')]` bridges an irregular collection plural so `includingPerson()` reaches `$people`, and `#[NotMagic]` seals a property from derivation - both read from one place (`PropertyResolver`) so the runtime and the analysis can never disagree. The bundled `MagicModifierMethodsExtension` teaches PHPStan every derived signature from the same `Prefix` semantics and never advertises a modifier the writers would refuse, so magic calls analyse at level max with zero annotations and no mapper. An IDE does not read the extension, so autocomplete for the derived calls comes from `@method` tags written by hand today and derived automatically by the Rector set landing in 2.0.0.
- **`AbstractBuilder`, the dependency-free kernel every concrete builder extends.** `create()` calls `seed()` exactly once, so the perfect default has exactly one home - and `seed()` is plain PHP, because the kernel imposes no randomness strategy - a constant, a `random_int()` suffix or a project-supplied generator are all equally welcome and none is required. `mutate()` is the immutability engine - clone, apply the change to the clone, return the clone - which makes every public modifier a one-liner and guarantees no builder instance is written after creation. It accepts a mutation closure or a plain property map - the dialect PHP 8.5's clone-with speaks, portable back to 8.3 through a scope-bound write - and the map form refuses a key naming no property the concrete scope can write, so a typo never becomes a silent dynamic property. Zero runtime dependencies.
- **A PHPStan rule set enforcing the DSL, bundled from day one.** Nine rules, one directory per abstraction type. `Rule/Class` seals concrete builders as final. `Rule/Method` restricts the public surface to the DSL, holds every modifier body to its prefix's promise (`without*` empties, `including*` appends, `excluding*` never appends, `having*` writes more than one property, and the feeding prefixes take parameters while `without*` takes none and `as*` at most one optional bool), requires every modifier to be a static-returning one-liner through `mutate()`, keeps `seed()` protected and free of modifier or `build()` calls (the returned clone would be silently discarded), demands a concrete non-nullable return type on `build()` and refuses non-static mutation closures - a non-static closure keeps `$this` bound to the original builder and could mutate the trunk behind `mutate()`'s back. The `mutate()`- and `seed()`-shaped rules apply only to builders that extend `AbstractBuilder`, so a hand-rolled `BuilderInterface` implementation keeps the contract rules without being ordered to delegate to a `mutate()` it never inherited. `Rule/Property` keeps builder state private, per-instance and never readonly, and requires every property to carry an inline default or a direct assignment in `seed()` - the per-property face of the perfect default. One `includes:` line for `config/extension.neon` turns the contract into analysis errors, and PHPStan itself stays an optional `suggest`.
- **`UnbuildableState`, the loud failure.** A builder driven into an impossible state throws instead of producing a broken object that fails far from its cause. Two factories compose the two message shapes - `missing()` for an absent ingredient, `contradiction()` for calls that cancel each other out - and both name the builder by its short class name and end with concrete guidance, so the failing test points straight at the fix.
- **The example suite - living documentation under `tests/Example`.** A readonly `User`, the `UserBuilder` that produces it, and the test that proves the three guarantees - the perfect default builds immediately, branches from one shared trunk never interfere, and the guard message reads exactly as promised. The README prints the same files verbatim.
